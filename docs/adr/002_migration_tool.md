# ADR 002: Выбор инструмента миграций

## Контекст
В практической работе №5 требуется перевести модель данных в работающую схему СУБД и настроить механизм миграций. Схема должна создаваться только через миграции, без ручного изменения таблиц в pgAdmin. Нам нужен инструмент, который сможет версионировать изменения структуры базы данных и легко разворачивать их на чистой базе.

## Решение
Мы выбрали **Alembic** (в связке с SQLAlchemy) в качестве инструмента миграций для проекта NorthwindApp.

**Обоснование выбора:**
1. **Стандарт для Python.** Alembic — это де-факто стандарт для Python-проектов, работающих с PostgreSQL.
2. **Автогенерация.** Инструмент умеет автоматически генерировать файлы миграций на основе моделей SQLAlchemy, что снижает риск человеческой ошибки.
3. **Поддержка откатов.** Alembic позволяет легко откатывать миграции (команда `downgrade`), что удобно при разработке.
4. **Альтернативы:** мы рассматривали Flyway и Liquibase, но они чаще используются в Java-экосистеме, а для нашего Python-проекта Alembic является наиболее нативным и простым решением.

## Последствия
- **Плюсы:** вся структура базы данных будет описана в коде (в папке `migrations/`), что позволяет развернуть проект одной командой `alembic upgrade head`.
- **Минусы:** разработчикам нужно изучить синтаксис Alembic и не забывать создавать новые файлы миграций при изменении структуры БД.
