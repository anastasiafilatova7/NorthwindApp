# Модель ветвления проекта NorthwindApp

## Выбранная модель: Упрощённый GitHub Flow

Для учебного проекта выбрана упрощённая модель GitHub Flow с единственной долгосрочной веткой `main`.

### Основные принципы

1. **Ветка `main`** — единственная долгосрочная ветка. В ней всегда находится стабильный, рабочий код.
2. **Прямые коммиты в `main` запрещены.** Все изменения вносятся через отдельные ветки и Pull Request.
3. **Для каждой задачи создаётся отдельная ветка** с говорящим именем:
   - `feature/<id>-<описание>` — для новой функциональности;
   - `docs/<id>-<описание>` — для документации;
   - `fix/<id>-<описание>` — для исправления ошибок;
   - `chore/<id>-<описание>` — для служебных задач.
4. **Именование коммитов** — по стандарту Conventional Commits:
   - `feat(#id): ...` — новая функция;
   - `docs(#id): ...` — документация;
   - `fix(#id): ...` — исправление;
   - `chore(#id): ...` — служебные изменения;
   - `refactor(#id): ...` — рефакторинг.
5. **Слияние в `main`** — только через Pull Request после одобрения (минимум 1 approve).

## Настройка защиты ветки `main`

- Запрещены прямые коммиты.
- Требуется минимум 1 одобрение через Pull Request перед слиянием.
- Опционально: требование успешного прохождения автоматических проверок (статус-чеков).

## Обоснование выбора

Модель GitHub Flow выбрана по следующим причинам:
- **Простота.** Не требует сложной инфраструктуры, подходит для команды из 2 человек.
- **Скорость.** Позволяет быстро вносить изменения через короткоживущие ветки.
- **Безопасность.** Защита `main` исключает случайные поломки стабильной ветки.
- **Совместимость.** Полностью поддерживается GitHub из коробки (Branch Protection Rules, Pull Requests).
