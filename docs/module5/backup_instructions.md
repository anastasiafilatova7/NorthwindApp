# Инструкция по резервному копированию и восстановлению БД Northwind

## 1. Введение
Данный документ описывает регламент резервного копирования (бэкапа) и восстановления базы данных PostgreSQL для проекта NorthwindApp. Инструкция предназначена для администратора, который видит проект впервые.

## 2. Значения RPO и RTO
- **RPO (Recovery Point Objective) — 24 часа.** Мы можем потерять данные максимум за последние сутки. Это обосновано тем, что для учебного проекта критична не каждая минута, а сохранение общей структуры и основных данных заказов.
- **RTO (Recovery Time Objective) — 2 часа.** Время, за которое администратор должен восстановить базу из резервной копии в случае сбоя. Этого времени достаточно для скачивания дампа и запуска команды восстановления.

## 3. Расписание и правила хранения
Мы используем упрощенную стратегию **3-2-1**:
- **3** копии данных (1 рабочая база + 2 резервные).
- **2** разных места хранения (локальный компьютер + облачное хранилище, например, Яндекс.Диск или Google Drive).
- **1** из копий хранится вне основного места (облако).

**График:**
- **Полная копия** — раз в неделю (по воскресеньям).
- **Разностная (инкрементальная) копия** — раз в сутки (каждый день в 23:00). Это быстрее и экономит место.

## 4. Команды для создания резервной копии
