# Использование ИИ-ассистентов и анализ рисков

## 1. Использование ИИ для генерации тестов

**Промпт (запрос к ИИ):**
> Напиши код модульных тестов на Python с использованием фреймворка `pytest` для функции `authenticate(username, password)` из файла `auth.py`. Функция проверяет логин и пароль по словарю и возвращает логин (роль) при успехе или `None` при ошибке. Напиши тесты для позитивного сценария (верные данные), негативного (неверный пароль) и негативного (несуществующий пользователь).

**Сгенерированный код:**
ИИ предложил код для файла `test_auth.py` с использованием библиотеки `pytest`. Были написаны тесты для позитивного и негативных сценариев.

## 2. Выявленные проблемы и их исправление

При ручной проверке сгенерированного кода были выявлены следующие недочеты:
1. **Отсутствие проверки всех ролей.** Изначально ИИ написал тест только для роли `manager`, хотя в словаре 4 роли. Необходимо расширить покрытие, добавив проверки для `boss`, `warehouse` и `personnel`.
2. **Отсутствие граничных случаев.** ИИ не догадался сразу проверить передачу пустых строк (`''`) или `None`.
3. **Неучтенный регистр.** ИИ не проверил, что логин чувствителен к регистру (например, `Manager` не должен проходить авторизацию).
Для исправления этих недочетов был добавлен еще один запрос, в котором прописано что именно требовалось исправить.

## 3. Ограничения и риски использования ИИ

1. **Поверхностный подход:** ИИ генерирует тесты только для тех данных, которые были явно указаны в промпте. Если не указать "проверь все роли", он напишет только одну.
2. **Отсутствие контекста:** ИИ не знает, как работает реальная база данных и графический интерфейс, поэтому он не может написать интеграционные тесты для кнопок Tkinter.
3. **Иллюзия правильного кода:** Сгенерированный код выглядит рабочим, но без ручной проверки он может пропустить важные баги.

**Вывод:** ИИ — это отличный помощник для написания шаблонного кода. Но он требует обязательной ручной проверки и доработки.
