# To-Be: целевой процесс учета клиентов и заказов

## Описание целевого процесса

После внедрения системы NorthwindApp все данные хранятся в единой
базе данных PostgreSQL. Каждая роль получает доступ только к своим
разделам через графический интерфейс.

### Как будет работать процесс

1. **Авторизация.** Сотрудник запускает приложение `main.py`,
   вводит логин и пароль. Система проверяет данные через `auth.py`
   и определяет роль.
2. **Работник склада** открывает окно `warehouse_window.py`:
   - видит список продуктов и категорий;
   - может добавлять, редактировать, удалять продукты;
   - может добавлять и удалять категории.
3. **Отдел кадров** открывает окно `personnel_window.py`:
   - видит список сотрудников;
   - добавляет, редактирует, удаляет сотрудников.
4. **Менеджер** открывает окно `manager_window.py`:
   - видит список заказов и клиентов;
   - создает заказы, редактирует страну доставки, удаляет заказы;
   - добавляет, редактирует, удаляет клиентов.
5. **Начальник** открывает окно `boss_window.py`:
   - видит 3 отчета (по клиентам, по сотрудникам, по категориям);
   - данные обновляются автоматически из БД.

## Точки автоматизации

| № | Что автоматизировано | Как |
|---|---|---|
| 1 | Авторизация и разграничение прав | `auth.py` + `main.py` |
| 2 | Учет продуктов и категорий | `warehouse_window.py` |
| 3 | Учет сотрудников | `personnel_window.py` |
| 4 | Учет заказов и клиентов | `manager_window.py` |
| 5 | Формирование отчетов | `boss_window.py` |
| 6 | Хранение данных | PostgreSQL, единая БД Northwind |

## Преимущества To-Be

- Единый источник данных — нет расхождений.
- Разграничение прав доступа по ролям.
- Отчеты формируются мгновенно.
- Снижение ошибок ручного ввода.
- Оперативность получения информации.
